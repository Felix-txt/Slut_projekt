CS Clicker backend setup and troubleshooting handoff
====================================================

Project layout
--------------
Repo root:
- server/            Node/Express backend API
- server/schema.sql  PostgreSQL database schema
- frontend/          Static HTML/CSS/JS frontend
- admin/             Static admin pages

Backend stack
-------------
- Node.js / npm
- Express
- PostgreSQL
- pg npm package
- JWT auth with jsonwebtoken
- bcryptjs password hashing

Install requirements on a new PC
--------------------------------
Install:
- Node.js 20 or newer
- npm
- PostgreSQL 15 or newer
- Git, if cloning the repo

Optional:
- Python 3, only needed to serve frontend with python -m http.server
- Docker Desktop, only needed if using docker-compose instead of local Postgres

Backend install
---------------
From the repo root:

cd server
npm install

Create server/.env:

DB_HOST=localhost
DB_USER=gameuser
DB_PASSWORD=your_password_here
DB_NAME=game_db
DB_PORT=5432
PORT=5000
JWT_SECRET=make_a_long_random_secret
ROOT_ADMIN_EMAIL=admin@test.local
ROOT_ADMIN_USERNAME=admin
ROOT_ADMIN_PASSWORD=your_admin_password
ROOT_ADMIN_CODE=your_private_admin_code

Database setup with local PostgreSQL
------------------------------------
Create the user and database:

psql -U postgres

Then in psql:

CREATE USER gameuser WITH PASSWORD 'your_password_here';
CREATE DATABASE game_db OWNER gameuser;
\q

Import the schema from the server folder:

cd server
psql -U gameuser -d game_db -f .\schema.sql

Start backend
-------------
From server/:

npm start

Expected output:

server running on http://0.0.0.0:5000

Frontend startup
----------------
The frontend is static files. From repo root:

py -m http.server 8080

Open:

http://localhost:8080/frontend/login-signin.html

Expected normal local ports
---------------------------
- Frontend: http://localhost:8080
- Backend API: http://localhost:5000
- PostgreSQL: localhost:5432

Current-machine note
--------------------
On Nathaniel's current PC, port 5000 is currently owned by postgres.exe, not the Node API.
The Node API is running on port 5001 instead.

That means any frontend code calling:

http://localhost:5000/api

will fail on this PC because it is talking to PostgreSQL, not Express.

Confirmed current behavior:
- http://localhost:5001/api/leaderboard returns HTTP 200 with JSON.
- http://localhost:5000/api/leaderboard fails because port 5000 is not HTTP/Express.

If this happens on another PC
-----------------------------
Check listeners:

PowerShell:
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in 5000,5001,5432,55432,8080,8090 }

Check process names:

Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -match 'server.js|npm|postgres|http.server' } | Select-Object ProcessId,Name,CommandLine

Fix options:
1. Preferred clean setup:
   - Run PostgreSQL on 5432.
   - Run backend on 5000.
   - Use PORT=5000 in server/.env.

2. If port 5000 is already taken:
   - Run backend on 5001.
   - Set PORT=5001 before npm start, or use a .env with PORT=5001.
   - Make frontend call http://localhost:5001/api.
   - Several frontend/admin pages include a fallback helper that tries 5001 before 5000.

Quick backend test commands
---------------------------
Test backend is reachable:

Invoke-WebRequest -UseBasicParsing http://localhost:5000/api/leaderboard

If backend uses 5001:

Invoke-WebRequest -UseBasicParsing http://localhost:5001/api/leaderboard

Expected good result:
- HTTP 200
- JSON body beginning with {"ok":true,...}

Useful API routes
-----------------
Auth:
- POST /api/auth/register
- POST /api/auth/login

Account:
- GET /api/users/me        Requires Authorization: Bearer <token>
- GET /api/users/:id       Public profile view
- PUT /api/users/update    Requires Authorization: Bearer <token>

Saves:
- POST /api/saves/save
- GET /api/saves/load/:gameId

Leaderboard:
- GET /api/leaderboard

Docker alternative
------------------
There is a server/docker-compose.yml that can run Postgres and the API together.
From server/:

docker compose up --build

This exposes:
- API on 5000
- PostgreSQL on 5432

Do not use Docker and a local PostgreSQL service on the same port unless one of them is moved.

Common failure causes
---------------------
1. ECONNREFUSED / could not connect:
   - Node backend is not running.
   - Wrong API port.
   - Firewall blocked the port.

2. Browser says could not connect to server:
   - Frontend points to localhost:5000 but backend is actually on 5001.
   - Or port 5000 is PostgreSQL, not Express.
   - In this repo, check old hardcoded API constants with: rg "localhost:5000|const API" frontend admin

3. Backend starts but database errors:
   - DB_HOST, DB_USER, DB_PASSWORD, DB_NAME, or DB_PORT in .env is wrong.
   - Database/schema was not created.
   - PostgreSQL service is not running.

4. Auth routes fail with invalid token:
   - JWT_SECRET changed after login.
   - Log out, clear localStorage, log in again.

5. New backend routes return 404 after code changes:
   - The Node server is still running old loaded code.
   - Restart npm/node backend.
