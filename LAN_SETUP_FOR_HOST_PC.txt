LAN setup for CS Clicker website/backend + game sync
====================================================

Goal
----
Host the website and backend on one PC on the local network, so other PCs and the game EXE can use:

http://192.168.1.126:8090

Important idea
--------------
The game does NOT talk directly to port 5001 when used from another PC.
The game talks to:

http://192.168.1.126:8090/api/...

share-server.js receives those /api requests and proxies them to the backend on the host PC:

192.168.1.126:8090/api -> 127.0.0.1:5001/api

This means only port 8090 needs to be reachable from other computers.


Install requirements on host PC
-------------------------------
Install:
- Node.js 20 or newer
- npm
- PostgreSQL 15 or newer
- Git, if cloning the repo

Optional:
- Docker Desktop, only if using docker-compose instead of local PostgreSQL

Create server\.env if missing:

If this PC uses PostgreSQL on another port, set DB_PORT to that port.
On Nathaniel's current PC, local dev has used DB_PORT=55432.

Then run:

Firewall
--------
Allow inbound TCP port 8090 on the host PC.

PowerShell as Administrator:

New-NetFirewallRule -DisplayName "CS Clicker LAN Web 8090" -Direction Inbound -Protocol TCP -LocalPort 8090 -Action Allow

Port 5001 does not need to be open to other PCs if they use port 8090.

How game sync works
-------------------
The game logs in:

POST /api/auth/login

The backend returns a JWT token.

The game saves cloud snapshot:

POST /api/saves/save

Payload includes:

{
  "gameId": "case-clicker",
  "snapshot": {
    "name": "Player",
    "money": 1234,
    "level": 10,
    "xp": 100,
    "totalXP": 100,
    "inventory": [],
    "inventoryCount": 0,
    "stats": {},
    "savedAt": 1716807200
  }
}

Backend stores the save by the JWT account id, so clients cannot choose another user's save id.

The account page loads the same cloud snapshot from:

GET /api/saves/load/case-clicker

Then it displays snapshot.inventory.


Important limitation
--------------------
This setup is for LAN/local network.
If deployed publicly on the internet, do NOT use 192.168.1.126 or localhost in the game/web clients.
Use a real domain or public IP, ideally HTTPS.


Common problems
---------------
1. Browser cannot open 192.168.1.126:8090
   - share-server.js is not running.
   - Host PC IP is different.
   - Windows Firewall blocks port 8090.

2. /api/leaderboard returns Backend is not reachable
   - share-server.js is running, but backend on 5001 is not running.
   - Start backend with PORT=5001.

3. Game login fails from another PC
   - The EXE was built before account_api_config.lua pointed to 192.168.1.126:8090.
   - Rebuild/repackage the EXE.
   - Check that curl.exe exists on the client PC.

4. Website works on host but not on another PC
   - Use ipconfig on host PC and confirm IPv4 address is 192.168.1.126.
   - Allow inbound firewall port 8090.
   - Make sure both PCs are on same network.

5. Inventory does not update on account page
   - Start/restart the game after latest sync changes.
   - Log in inside the game.
   - Change inventory.
   - Wait up to 30 seconds for autosave/cloud sync, or close game normally to trigger final sync.
   - Refresh account page.
